# Дружище. Шаблон агента навыков

## Общий цикл

1. Агент получает задание и проверяет входные данные.
2. Исполнитель делает действие. Проверка отдельно читает результат из файла, интерфейса или другого источника, где видно фактическое состояние.
3. При успехе агент выдаёт результат. Если результат можно подготовить отдельно, он публикуется после сверки.
4. При расхождении агент ищет в рабочей памяти профиль для этого навыка и набора признаков сбоя. Он применяет профиль на новой попытке и повторяет сверку.
5. Если подходящей записи нет или она не помогла, агент запрашивает у локальной Qwen выбор из разрешённых профилей. Для Блокнота используется `qwen2.5:14b`.
6. Профиль сохраняется после успешной повторной сверки. Если сверка снова не прошла, агент фиксирует причину. Он может выбрать другой профиль, если адаптер заново разрешил повтор. Лимит составляет две попытки восстановления. Ошибка в рабочей памяти или отсутствие подходящего профиля отражаются в журнале.
7. Учебные сбои и их профили хранятся отдельно. В журнале видны попытка, источник профиля, проверка и итог.

## Что добавлять для каждого навыка

- Одно конкретное действие и его рабочий запуск.
- Входные данные и признак успешного выполнения.
- Проверку фактического результата и разрешённые способы восстановления.
- Отдельную область памяти для навыка, чтобы профиль одного действия не применялся к другому.
- Один сквозной прогон на целевой системе для проверки нового действия и его результата.

## Реализация в агенте «Блокнот»

- В версии 0.3.8 два запуска на Windows 11 подтвердили, что профиль можно сохранить после сверки файла и использовать после перезапуска без повторного запроса к Qwen. Проверялся учебный сценарий.
- Версия 0.3.9 добавляет запись пользовательской заметки и выдачу готового файла после сверки. Этот режим проверен с имитацией Windows.
- В комплекте 0.4.5 пункт 3 Блокнота использует общий модуль `skill_engine.py`. Выбор профиля, проверка ответа Qwen и запись в SQLite находятся в модуле. Запуск окна, пробные документы и проверка состояния Блокнота находятся в его адаптере.

## Подключение следующего агента

1. Возьми `skill_engine.py`. Модуль использует стандартную библиотеку Python 3.11.
2. Реализуй `action(profile)`. При `profile is None` выполняется штатный способ. Для каждого разрешённого профиля действие задаётся заранее в коде агента.
3. Реализуй `verify(result)`. Функция должна прочитать фактическое состояние и вернуть `True` только после подтверждения.
4. Реализуй `profiles_for_error(error)`. Она возвращает словарь идентификаторов и описаний разрешённых вариантов. При риске повторного внешнего действия верни пустой словарь.
5. Вызови `run_skill` с уникальными именами агента и навыка и путём к SQLite. Для учебных прогонов укажи отдельную базу. В рабочем режиме результат находится в `outcome.evidence`, а статус в `outcome.status`.

```python
from skill_engine import run_skill

outcome = run_skill(
    agent="имя_агента",
    skill="имя_навыка",
    action=action,
    verify=verify,
    profiles_for_error=profiles_for_error,
    memory_path="recovery.sqlite3",
)
```

Для агента, который сначала выполняет все штатные проверки и только потом
разбирает сбои, есть `recover_skill`. Такой вход используется в пункте 3 Блокнота.
Журнал подключается через `report(stage, status, **details)`.
В комплекте проверку ядра можно запустить командой `py -3.11 -m unittest -v test_skill_engine`.
