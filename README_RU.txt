Дружище · Агент Блокнот · версия 0.3.9

Запись своей заметки
1. Откройте Данные/Задания/TASK.txt в Блокноте, замените пример своим текстом и сохраните
   файл в UTF-8. Допустимо до 1000 символов, включая переносы строк.
2. Запустите START_WRITE_NOTE.cmd. Пока агент печатает и сохраняет черновик,
   не переключайте вкладки и окна. Ollama понадобится при расхождении, если
   сохранённый профиль отсутствует или не прошёл повторную сверку.
3. При успешной сверке путь к готовой заметке появится в окне журнала.
   Откройте папку «Данные/Готово». Каждая заметка получает новое имя.
4. Отчёт о записи находится в Данные/Журналы/*_WORK_REPORT.txt.
   При ошибке готовая заметка не публикуется, а причина попадает в отчёт.

Дополнительные режимы проверки

1. Распакуйте архив в новую папку. Скопируйте свой TASK.json в «Данные/Задания».
   Если файла нет, в этой папке скопируйте TASK.example.json под именем TASK.json.
2. При необходимости проверьте наличие qwen2.5:14b командой ollama list.
   Это единственная модель диагностики по умолчанию.
   Другой тег можно задать переменной NOTEPAD_QWEN_MODEL.
3. Запустите START_TRAINING.cmd. Во время серии оставьте фокус на Блокноте.
4. После завершения пришлите Данные/Журналы/*_REPORT.txt.

Данные/Задания/TASK.json принимает до 1000 символов. Переносы Windows и Unix сравниваются как LF.
Серия проверяет 30 текстов, включая перенос строки и табуляцию, по содержимому файлов на диске.
Если файл отличается ровно одним лишним переносом в конце, стенд удаляет
его в тестовой вкладке и заново сверяет файл. Стенд проверяет активное окно
и уникальное имя файла, допуская изменение отметки редактирования в заголовке.
При другом несовпадении стенд сначала ищет сохранённый профиль по признакам
сбоя и перепроверяет его на новом файле. Если профиля нет или он не помог,
стенд один раз обращается к Qwen. Выбранный Qwen профиль сохраняется только
после точной сверки текста на диске. Рабочая память находится в
Данные/Память/recovery_memory.sqlite3 и сохраняется между запусками.
Каждая новая попытка работает со свежим тестовым файлом. При потере фокуса
или другой ошибке автоматизации серия прерывается с отчётом.
Если все тесты проходят, Ollama не вызывается. Время каждого вызова
диагностики сохраняется в Данные/Журналы/events.jsonl.
Рабочие Python-файлы не меняются. Профиль применяется в рамках серии.
Реестр стенда фиксирует результаты и последний профиль, прошедший проверку.


Отдельная проверка восстановления
Запустите START_RECOVERY_TEST.cmd. Для этого режима Данные/Задания/TASK.json не нужен.
Стенд введёт известную строку с намеренно добавленным символом ! и сверит файл.
После подтверждения именно этого расхождения стенд запросит у Qwen разрешённый
профиль для повторной записи на новом тестовом файле. Если модель недоступна,
вернёт неподходящий ответ или повторная сверка не пройдёт, тест покажет сбой.
Успех означает, что повторная запись полностью совпала с ожидаемой строкой.
Результаты записываются в Данные/Журналы/*_RECOVERY_REPORT.txt и recovery_events.jsonl.
Отчёт обычной серии и реестр навыка этот режим не обновляет.

Проверка памяти между запусками
1. Запустите START_MEMORY_TEST.cmd. Данные/Задания/TASK.json для этого режима не нужен.
2. Дождитесь итога. В новом каталоге первый запуск должен показать
   recovered: 1, selected_by: qwen2.5:14b и memory_saved: true.
3. Закройте окно журнала после завершения и запустите тот же CMD из той же
   папки ещё раз. Ожидаемый итог — recovered: 1 и selected_by: memory.
4. Откройте Данные/Журналы/*_MEMORY_REPORT.txt и Данные/Журналы/memory_events.jsonl.
   В журнале первого запуска ожидаются diagnosis и memory/saved,
   в журнале второго — memory/hit без запроса к Qwen.

Тест добавляет лишний символ при любом профиле с паузой перед Ctrl+S
менее 2 секунд. Это специально заданное условие учебного теста.
Учебная память находится в Данные/Память/recovery_memory_test.sqlite3.
Рабочий режим и тест памяти используют разные базы.

Окна во время проверки
Запустите CMD двойным щелчком, чтобы журнал был в отдельном окне.
Стенд размещает журнал слева, Блокнот справа на том же мониторе.
Если Windows Terminal скрывает заголовок, стенд может распознать только
Блокнот. В этом случае можно поставить окно журнала слева через Win + ←
до запуска проверки из терминала. Во время ввода фокус нужен Блокноту.
После проверки агент закрывает опознанную пробную вкладку. Текст сохраняется в «Данные/Тесты».

Новые отчёты получают общий порядковый номер, дату и местное время Windows.
Точное имя печатается в консоли. Пример имени отчёта
1_2026-11-08_17-42-06_Notepad_Clipboard_Report.txt
